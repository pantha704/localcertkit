# certkit

Gate-0 feasibility spike: **fully in-browser PKCS#12 (.pfx/.p12) handling — no server, no upload.**

A static page parses a PKCS#12 file with [node-forge](https://github.com/digitalbazaar/forge), shows the
private key + certificate chain, verifies the key matches the certificate, and exports PEM for both.

## Quick start

```bash
open index.html            # works straight from file:// — forge is vendored, no network calls
```

Or serve it anywhere static. Nothing is uploaded; parsing happens in the page.

## Repo layout

```
index.html            # static page: file input, password, results, copy/download PEM
app.js                # DOM wiring (uses global `CertKit`)
lib/certkit.js        # parse/inspect/verify/export logic (UMD: browser global + CommonJS)
vendor/forge.min.js   # node-forge 1.4.0 portable build (vendored; SHA256 in commit history)
fixtures/             # test PKCS#12 files (throwaway self-signed keys) + openssl ground truth
scripts/make-fixtures.sh
tests/node-smoke.mjs  # same lib in Node against every fixture
tests/browser-test.mjs# real Chromium (playwright-core), drives the UI on file://
tests/write-path.mjs  # PEM -> PKCS#12 via forge, verified by OpenSSL
tests/out/*.json      # captured evidence
EVIDENCE.md           # what passed/failed, numbers, Gate-1 verdict
```

## Reproduce

```bash
bun install                # node-forge + playwright-core (browser binary not needed)
bun run fixtures           # regenerate fixtures with openssl 3.x
bun run test               # node smoke + headless browser run
node tests/write-path.mjs  # pem -> pfx write path vs OpenSSL
```

Browser tests use `~/.cache/ms-playwright/chromium-1243/chrome-linux64/chrome` by default
(override with `CHROME_PATH`).

> The `fixtures/` directory contains **throwaway self-signed test keys generated by the script** —
> they are safe to commit and must never be used for anything real.
